# Triage

Triage the specified issue through the state machine.

## Labels

**Category** (pick one): `bug` | `enhancement`

**State** (pick one): `needs-triage` | `needs-info` | `ready-for-agent` | `ready-for-human` | `wontfix`

Each triaged issue requires exactly one category label and one state label.

## Workflow

### 1. Gather context
Read the full issue, prior comments, and relevant areas of the codebase.

### 2. Recommend category and state
Provide your reasoning. If it's a bug, attempt to reproduce it before proceeding.

### 3. If more info is needed
Use `/grill-with-docs` to identify the missing details, then post a `needs-info` comment using the template below.

### 4. Apply outcomes
Post the appropriate comment and apply labels.

## State Transitions

```
unlabeled → needs-triage → needs-info
                         → ready-for-agent
                         → ready-for-human
                         → wontfix
```

The maintainer can override transitions at any time.

## Comment Templates

**All triage comments must begin with**: *"This was generated by AI during triage."*

### needs-info template

> This was generated by AI during triage.
>
> **What we know so far:**
> [established facts]
>
> **Questions:**
> 1. [specific, actionable question]
> 2. [specific, actionable question]

### ready-for-agent / ready-for-human

Write an agent brief: a concise description of what needs to be built, the acceptance criteria, and any relevant context from the codebase.
